Purpose & context Brian Bevis is a Board of Directors member for Center Grove Bantam Football League (CGBFL), responsible for player personnel and overall player experience. His work spans league operations, web development, and digital infrastructure — building a suite of interconnected tools to modernize how CGBFL manages drafts, player evaluations, game-day operations, and sponsor relationships. The organization's teams are the Trojans, and Brian works within an established technical stack across multiple ongoing projects. Key stakeholders include league coaches, board members, and external partners (current sponsor outreach has included BAM Weather). The broader vision is a fully integrated digital presence: public-facing website, admin tools for coaches and board members, live streaming across multiple fields, and JSON-driven data management throughout. Current state Brian maintains and actively develops several single-file HTML applications, all following a consistent architecture: Trojans Command Center (Bantamdraft repo, GitHub Pages) — combined player rankings and live draft board for tackle football Flag Football Command Center — parallel tool adapted for flag football rules, separate JSON data files, recently debugged through CSV import issues and a script initialization bug ProBowl Nomination app — coach-facing Player of the Game nomination tool with schedule management and game-aware form auto-population Camp Check-In app — registrant check-in with QR code, admin roster import, and multi-device merge logic Field Status system — public badge + admin control panel for displaying Open/Delayed/Closed field conditions CGBFL homepage mockup — scoreboard-style homepage with weather, field status, ticker, scores, and sponsor strip Supporting pages (Rules & Policies, Coach's Corner) have been built as standalone HTML files with patterns for wiring to GitHub-backed JSON data. A recent sponsorship pitch to BAM Weather concluded with a decline (budget already allocated), but the relationship was kept warm with a follow-up reply. Brian built a full sponsorship pitch deck and one-page proposal PDF for that effort. On the horizon Continued build-out of the CGBFL website (cgbfl.com / cgbfl.sportngin.com), including wiring mockup pages to live JSON data sources Potential expansion of the live streaming setup to all 5 fields using XbotGo Falcons (~$3,000 target budget), with OBS used for sponsor overlays on featured fields Future sponsorship outreach cycles (BAM Weather flagged as a revisit when their budget resets) Cloudflare Worker allowlist updates needed as new JSON filenames are added with each new app Key learnings & principles GitHub secret scanning: PATs embedded in public HTML files get automatically revoked — all GitHub API access must route through the Cloudflare Worker proxy, and token-containing files must never be committed to any repo Cloudflare Worker routing: WORKERURL must not have a trailing slash; paths are concatenated directly, so double-slash URLs cause routing failures Script initialization order matters: Constants used in derived maps (e.g., DIVISIONKEYMAP) must be declared after their dependencies — temporal dead zone errors crash the entire app silently on load SportsEngine iframe constraints: Pasting HTML with <script> tags or full body/html CSS inline into SportsEngine's Code Element breaks execution and can corrupt the parent page's navigation — all tools must be hosted on GitHub Pages and embedded via <iframe> CSV import robustness: Header aliases and value normalization (e.g., fuzzy division matching stripping ordinal suffixes, punctuation, and "grade" keywords) are essential since real-world CSV exports rarely match exact expected formats Multi-device write safety: Read-modify-write with retry logic is required for any app where multiple users may submit data simultaneously Approach & patterns All tools are built as single-file HTML applications — self-contained, portable, and deployable by dropping a file into a GitHub repo Data persistence pattern: Cloudflare Worker proxy (WORKERURL) → GitHub Contents API → JSON files in brianbevis-dotcom/CGBFL-Website (branch: main); Worker returns raw GitHub API responses (base64 content + SHA); PUT requires base64 content, SHA, and commit message Consistent design system: Red/black/white color scheme, Anton and Barlow Condensed fonts, Trojan helmet logo (base64-embedded) Division taxonomy: Tackle divisions are JRT, Rookie, Minor, Major, 2-4 GFL, 5-6 GFL, 7-8 GFL;
